# Avito ↔ Telegram Bridge Bot

Автоматический бот для интеграции Avito Messenger с Telegram, использующий LLM для генерации ответов.

<!-- Тест GitHub Actions деплоя -->

## Возможности

- 🤖 **Автоматические ответы** на сообщения из Avito через LLM (OpenAI GPT)
- 📚 **База знаний (Knowledge Cards)** с автоматическим извлечением из переписок
- 🎓 **Обучение манере общения** - бот копирует стиль менеджера из переписок
- 📎 **Загрузка файлов с переписками** - автоматическое извлечение знаний из больших файлов
- 🔍 **Семантический поиск** - умный поиск по базе знаний с ранжированием
- 💬 **Telegram бот** для управления и ответов менеджеров
- 🔄 **Умная логика пауз**: бот автоматически останавливается при передаче менеджеру
- ⏱️ **Cooldown после ответа менеджера**: бот не отвечает 15 минут после ответа менеджера
- 🎯 **Приоритизация источников знаний** - четкая иерархия источников информации

## Быстрый старт

### 1. Установка зависимостей

```bash
python3 -m venv .venv
source .venv/bin/activate  # На Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Настройка конфигурации

Скопируйте `.env.example` в `.env` и заполните все необходимые переменные:

```bash
cp .env.example .env
```

Обязательные переменные:
- `TELEGRAM_BOT_TOKEN` - токен Telegram бота (получить у @BotFather)
- `MANAGERS` - Telegram user ID менеджеров (через запятую), кому слать уведомления
- `AVITO_ACCOUNT_ID` - ID аккаунта компании в Avito (числовой ID)
- `AVITO_CLIENT_ID` / `AVITO_CLIENT_SECRET` - credentials приложения Avito (если один набор на все аккаунты)
- `AVITO_ACCOUNTS_CREDENTIALS_JSON` - (рекомендуется) per-account credentials в виде JSON в env
- `OPENAI_API_KEY` - ключ API OpenAI

Опциональные переменные:
- `LLM_MODEL` - модель LLM (по умолчанию: `gpt-4o`)
- `TEMPERATURE` - температура для LLM (по умолчанию: `0.2`)
- `COOLDOWN_MINUTES_AFTER_MANAGER` - пауза после ответа менеджера (по умолчанию: `15`)
- `ADMINS` - список ID администраторов через запятую
- `PUBLIC_BASE_URL` - публичный URL для webhook (например, `https://your-domain.com`)
- `LOG_LEVEL` - уровень логирования (DEBUG/INFO/WARNING/ERROR)
- `LOG_PII` - логировать ли тексты/истории (0/1). По умолчанию 0 (privacy).
- `LOG_WEBHOOK_PAYLOAD` - логировать ли raw webhook payload (0/1). По умолчанию 0 (privacy).

### 3. Запуск бота

```bash
python main.py
```

Бот запустит:
- Flask сервер на порту 8080 для обработки webhook от Avito
- Telegram бота для обработки команд и сообщений

### 4. Подписка на webhook от Avito

После запуска бота и настройки `PUBLIC_BASE_URL`, подпишитесь на webhook:

```bash
python manage.py subscribe
```

Или через Telegram бота командой `/subscribe` (требуются права администратора).

## Использование

### Telegram бот

**Команды для пользователей:**
- `/start` - приветствие
- `/help` - справка
- `/reset` - сбросить контекст (историю) для этого чата

**Команды для администраторов:**
- `/status` или `/botstatus` - управление ботом (on/off, режимы, модель)
- `/accounts` - Avito аккаунты (multi-account)
- `/knowledge` или `/kb` - управление базой знаний
  - Добавление знаний из текста
  - Загрузка файлов с переписками
  - Просмотр и управление карточками
  - Извлечение знаний из переписок
- `/staticcontext` - управление статическим контекстом
- `/dynamiccontext` - управление динамическим контекстом (цены, сроки)
- `/systemprompt` - управление системным промптом (манера поведения)
- `/subscribe` - подписаться на webhook от Avito
- `/unsubscribe` - отписаться от webhook

**Обычные сообщения:**
- Бот автоматически отвечает на вопросы пользователей через LLM
- Использует FAQ, историю диалога и статический контекст

**Обратная связь:**
- 👍 - добавить ответ в FAQ
- 👎 - уведомить о необходимости передачи менеджеру

### Avito → Telegram

1. Сообщение от клиента приходит в Avito
2. Avito отправляет webhook на `/avito/webhook`
3. Бот уведомляет менеджера в Telegram
4. Бот автоматически генерирует ответ через LLM (если бот активен)
5. Ответ отправляется в Avito

### Telegram → Avito

**Способ 1: Reply на уведомление**
- Ответьте на уведомление бота с Avito Chat ID
- Ваш ответ будет отправлен в Avito

**Способ 2: Текст с Avito Chat ID**
- Отправьте сообщение в формате: `Avito Chat ID: <id> ваш ответ`
- Ответ будет отправлен в Avito

## Логика работы бота

### Обзор

Бот представляет собой интеллектуальную систему автоматических ответов, которая:
- 🤖 Автоматически отвечает на вопросы клиентов через LLM
- 📚 Использует структурированную базу знаний (knowledge cards)
- 🎓 Обучается на переписках менеджеров для копирования манеры общения
- 🔄 Динамически обновляет знания из переписок
- 📊 Использует приоритизированные источники знаний

**Подробная документация:** [BOT_LOGIC.md](BOT_LOGIC.md)

### Автоматические ответы

Бот автоматически отвечает на сообщения из Avito, если:
- ✅ Бот не находится в паузе (не ожидает менеджера)
- ✅ Не истек cooldown после ответа менеджера
- ✅ Сообщение направлено от клиента (не от бота)

### Построение контекста для LLM

Бот использует следующие источники знаний (в порядке приоритета):

1. **Knowledge Cards** - структурированные знания по темам
   - Автоматически извлекаются из переписок
   - Ручное добавление админом
   - Семантический поиск с ранжированием

2. **Dynamic Context** - актуальные цены, тарифы, сроки
   - Обновляется администратором
   - Всегда используется для текущих цен и сроков

3. **Static Context** - миссия компании, описание услуг

4. **Примеры манеры общения** - всегда включаются в контекст
   - Извлекаются из переписок менеджеров
   - Используются для обучения стилю общения

5. **Dialogue Context** - последние сообщения диалога

### База знаний (Knowledge Cards)

**Структура:**
- Темы с фактами
- Категории для организации
- Приоритеты и релевантность
- Автоматическое извлечение из переписок
- Ручное добавление админом

**Категории:**
- Визы (шенген, другие страны)
- Документы, стоимость, сроки
- Процесс оформления
- Особые условия
- **Манера общения** - примеры стиля менеджера

**Подробнее:** [KNOWLEDGE_BASE_SYSTEM.md](KNOWLEDGE_BASE_SYSTEM.md)

### Обучение манере общения

Бот автоматически извлекает примеры манеры общения менеджера из переписок:
- Как приветствует клиентов
- Как формулирует ответы (просто, без канцелярита)
- Какие фразы использует
- Тон общения (доброжелательный, спокойный)
- Использование эмодзи

Эти примеры **всегда** включаются в контекст промпта для обучения бота правильному стилю общения.

### Паузы бота

Бот переходит в паузу в следующих случаях:

1. **Бесконечная пауза** (ожидание менеджера):
   - Бот сгенерировал ответ с сигнальной фразой (например, "ответит менеджер")
   - Бот ждёт ответа менеджера до получения ответа

2. **Временная пауза** (cooldown):
   - После ответа менеджера бот молчит 15 минут (настраивается)
   - Затем бот снова становится активным

### Сигнальные фразы

Если бот генерирует ответ с одной из этих фраз, включается бесконечная пауза:
- "по данному вопросу вам в ближайшее время ответит наш менеджер"
- "ответит наш менеджер"
- "наш менеджер ответит"
- "свяжется менеджер"
- "свяжется наш менеджер"

## CLI утилита

Используйте `manage.py` для управления через командную строку:

```bash
# Подписка на webhook
python manage.py subscribe [--url URL]

# Отписка от webhook
python manage.py unsubscribe [--url URL]

# Список подписок
python manage.py subs

# Список чатов
python manage.py chats [--limit N] [--offset N] [--unread-only] [--types u2i u2u]

# Информация о чате
python manage.py chat <chat_id>

# Список сообщений
python manage.py msgs <chat_id> [--limit N] [--offset N]

# Отметить чат как прочитанный
python manage.py read <chat_id>

# Отправить текстовое сообщение
python manage.py send-text <chat_id> <text>

# Отправить изображение
python manage.py send-image <chat_id> <file_path>
```

## Разработка

### Структура кода

Проект следует принципам:
- **Разделение ответственности**: каждый модуль отвечает за свою область
- **Типизация**: все функции имеют type hints
- **Документация**: все функции имеют docstrings
- **Обработка ошибок**: все критические операции обрабатывают исключения
- **Логирование**: важные события логируются с соответствующим уровнем

### Улучшения для production

Для production окружения рекомендуется:

1. **Хранилище сессий**: заменить in-memory хранилище на Redis или БД

3. **Очереди**: использовать очереди (Celery, RQ) для асинхронной обработки
4. **База данных**: хранить историю и FAQ в БД вместо JSON файлов
5. **Кэширование**: кэшировать токены и часто используемые данные
6. **Rate limiting**: добавить rate limiting для webhook endpoints
7. **Безопасность**: добавить аутентификацию для webhook (проверка подписи)
